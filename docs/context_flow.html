🗼 sts2-agent · 每次 LLM API 请求发送了什么

每个需要决策的游戏状态都会触发一次独立的 POST /chat/completions。 API 本身无状态，每个请求都自包含：卡牌/遗物定义在需要时随当前状态重新发送，模型从不需要"记得上一次请求"。 可用参数：max_history_turns = 8 max_state_chars = 4000（仅历史摘录） max_context_chars = 24000（预算只裁剪历史） decision_attempts = 3（共享同一 deadline） llm_retries = 0（单次 HTTP 传输重试） agent_timeout = 90s（游戏端每决策窗口，可调 10–300s） decision_budget = agent_timeout − 4s（共享 deadline 公式）

〇、两条最高原则（已写入 system prompt 并由格式化器落实）

1. HUMAN-VISIBLE INFORMATION PARITY — 人类玩家在当前 UI 能无成本查看的信息（屏幕、悬停提示、牌堆查看器、地图、遗物/药水/卡牌 tooltip、升级预览等），LLM 必须以等价文本形式收到；人类当前不知道的信息，LLM 绝不能收到：

禁止泄露：抽牌堆真实顺序（bridge 只发送无序组成，与游戏内牌堆查看器一致）· RNG/seed/下一次随机数 · ? 地图节点背后的真实房间类型 · 敌人未显示的未来 move · event 隐藏结果 · 内部 AI state / debug flags / 内部计数器（遗物只发送 UI 可见的 counter 与 used-up 状态）。

2. SOURCE OF TRUTH PRIORITY（高 → 低）：

1. Current runtime game state and current UI-visible values
2. Current runtime label / description text（mod 直接截图自 UI 节点）
3. Static knowledge base（docs/CARDS_REFERENCE.md / RELICS_REFERENCE.md /
   POWERS_REFERENCE.md —— 全部从当前游戏 build 反编译解析，非 Wiki）
4. Hardcoded mechanic glossaries（POWER/INTENT/KEYWORD）

冲突时永远信任更高优先级来源。格式化器把静态文本标注为
"static reference"，绝不覆盖 runtime 数值（如当前费用 vs 基础费用）。

三、单次决策时序（共享 deadline / 重试 / 兜底 / 终止）

sequenceDiagram participant G as 游戏 bridge_mod participant A as Agent 工作线程 participant L as LLM API G->>A: 状态 JSON（等待一个动作，agent_timeout 窗口） A->>A: format_state + RunMemory.observe + 组装 messages Note over A: decision_deadline = 现在时刻 + hard_deadline

所有重试共享这一个 deadline loop decision_attempts = 3 次（剩余时间 < 2s 则停止） A->>L: messages 全量发送（本次限时 = 剩余时间） L-->>A: 单个 JSON 对象（thought + action） A->>A: extract_json（含 json-repair 修复） A->>A: validate_action（范围/能量/目标/enabled/min-max 选择数/skip 合法性） alt 解析或校验失败 A->>A: 反馈=前一个动作+错误原因+合法 schema 提示，重试 end end alt 全部失败或 deadline 耗尽 A->>A: fallback_action（确定性安全动作，绝不随机） end A->>G: 动作 JSON（play / end_turn / potion / choose / skip） A->>A: 决策写入历史 + 日志 + logs/run_*.jsonl Note over G,L: 超过 agent_timeout → 游戏端终止 run（result=terminated）

术语区分：transport_retries（llm_retries，单次 HTTP 调用的传输重试，默认 0）≠ decision_validation_attempts（decision_attempts，同一状态最多 3 次解析/校验尝试，共享同一 deadline）。重试反馈包含：前一个动作、被拒原因、"当前状态未变、以上文本仍然准确"、以及本屏合法 schema 指引。
